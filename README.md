# NeoBookMarkManager v1.0

ブックマークHTML（Netscape形式）を読み込んで、整理・情報の補完・タグ付け・AI分類・リンク切れチェックを行うデスクトップアプリ。Tauri + axum + 素のHTML/CSS/JSで、EXE 1本のポータブル構成。

対応環境: Windows（開発・動作確認とも Windows 11）。

バージョン: **1.0.0** — 変更履歴は [CHANGELOG.md](CHANGELOG.md)、リリース手順は [RELEASING.md](RELEASING.md)。

---

## できること

**整理**
- 重複ブックマークの削除、同名フォルダの統合、ドメイン別の集約・並べ替え
- 2画面ツリーでのドラッグ移動、フォルダ/ブックマークの追加・編集・削除
- すべての編集は Undo / Redo（Ctrl+Z / Ctrl+Y）で戻せる

**情報を補う**
- 「⚡まとめて取得」の1ボタンで、タイトル・説明文をWebから取得し、続けてローカルでタグを付ける
- 取得済みかどうかをダッシュボードで表示（タイトル / 説明文 / タグ の件数と割合）
- 取得を試みて何も無かったページは「取得不可」として数え、毎回追いかけない
- リンク切れチェックと、切れたものの一括削除

**AI分類（Gemini）**
- 全件からフォルダ構成を先に決め、その構成に沿って振り分ける2段階方式
- 提案は必ずレビュー画面を経由し、信頼度で絞り込んでから適用する
- 送信前に件数と概算コストを表示。単価が分からないモデルは実行をブロックする

**安全性**
- 破壊的な一括処理（AI適用・一括整理・保存）の直前に、必ずバックアップを作成する。作成に失敗したら処理を中止する
- バックアップは30世代まで保持し、「直前に戻す」「一覧から復元」で戻せる
- DBのスキーマ移行前に `user_data.db.bak-vN` を作り、移行に失敗したら自動で戻す

## セットアップ

### ビルド

```powershell
cargo tauri build --no-bundle
```

`target/release/NeoBookMarkManager.exe` が単体で生成されます（インストーラは作りません。`bundle.active` を `tauri.conf.json` で `true` にすればMSI/NSISも作れます）。

このEXEは**どこに置いても動く**ポータブル構成です。初回起動時に、EXEと同じフォルダに以下を自動生成します。

```
NeoBookMarkManager.exe
config/
  config.ini       ← 設定（APIキーなど）
  models.json      ← Geminiモデルの価格表
data/
  bookmarks.html   ← 初回用の空ファイル
  user_data.db     ← 取得済みタイトル・タグ・セッション情報
backups/           ← 世代バックアップ（最新30世代）
logs/
  ai_classify.log  ← AI分類の実行ログ
```

> **注意**: 開発ツリーの `target/release/` にビルドしても、実際に使っているフォルダに自動ではコピーされません。EXEを差し替えるときは手動でコピーしてください。ログやバックアップは、**EXEを置いたフォルダ**の下に作られます。

### AI機能（Gemini）のAPIキー設定

`config/config.ini` の `[API]` セクションを編集します。

```ini
[API]
api_key = あなたのAPIキー
```

アプリ内の「AI設定」画面からも保存できます（`POST /config/api-key` 経由で同じファイルに書き込みます）。

環境変数 `GENAI_API_KEY` / `GOOGLE_API_KEY` を設定すると、`config.ini` より優先されます。通常は使わなくてOKです。

## 使い方の流れ

1. **開く**（Ctrl+O）— ブックマークHTMLを選ぶ。次回の起動時は、前回開いていたファイルが自動で開きます。
2. **情報を補う** — 「⚡まとめて取得」を実行。AI分類の精度は、ここで入る情報の量に大きく左右されます。
3. **操作の対象を選ぶ** — 「選択中 / フォルダ / 全体」。整理・補完・AIのすべてがこの範囲に対して動きます。
4. **AIでフォルダ分類** — 件数とコストを確認して実行し、提案をレビューしてから適用。
5. **保存**（Ctrl+S）— 保存の直前にバックアップが作られます。

気に入らなければ Ctrl+Z で戻せます。保存後でも「直前のバックアップに戻す」で戻せます。

## AI分類の仕組みと設定

**2段階**

1. 全ブックマークのドメイン・タイトル・タグだけを1回送り、**フォルダ構成だけ**を決めさせる。
2. その構成を全リクエストに固定で渡して、実際の振り分けを行う。

1回のリクエストで収まる件数でも構成決定を行います（既定150件、AI設定のスライダーで10〜300件）。これにより、区切り方で結果が変わりません。構成決定に失敗した場合は、従来どおり順に学習しながら振り分けます。

**フォルダの作られ方**

- AIが新しく作るフォルダは、作成先の下で**2階層まで**（`Guitar/Gear` は可、`Guitar/Gear/Amps` は `Guitar/Gear` に切られます）。
- 新しいフォルダは2件以上のときだけ作られます。1件だけのものは、同じ親にまとまりがあれば親へ、無ければ「その他」へ。
- 構成決定の段階では、件数に見合う数（件数÷8、5〜60個）を目安として指示します。

**コストとプライバシー**

- 送信前に件数と概算コスト（入力・出力）を表示し、承認してから送ります。
- 単価が `config/models.json` にも `config.ini` にも無いモデルは、**一切送信せず実行をブロック**します。
- URLのクエリ文字列は、既定で送信前に削除します。
- APIキーが無料枠か有料枠かを自己申告できます。**無料枠はGoogleが内容を製品改善に利用し、人間がレビューする場合があります**。送るのはブックマークのタイトルとURLなので、どちらの枠で使っているかは把握しておいてください（ヘルプ画面 F1 に詳細）。

**うまくいかないときは**

`logs/ai_classify.log` を見てください。1回の実行ごとに、次が残ります。

- `plan=true/false` … 構成決定を行ったか
- `plan ok: N folders: ...` … 決まったフォルダ一覧
- `raw folders (N distinct): ...` … AIが実際に返したフォルダ名と件数（後処理の前）
- `catchall=N` … 「その他」に落ちた件数

`raw folders` の種類が極端に多い、`catchall` が多い、といった症状の切り分けに使えます。

>
> モデルが利用不可になった場合、アプリはその場でAI分類を停止し、AI設定画面で別のモデルに切り替えるよう案内します（未処理分は失われず再実行できます）。ただし「まだ動くと思って設定していたら実は廃止されていた」という事前検知は行っていません。

## データの扱い

| 置き場所 | 中身 | 消えるタイミング |
|---|---|---|
| `bookmarks.html` | ブックマーク本体、フォルダ構成、説明文 | 保存時に上書き（直前にバックアップ） |
| `data/user_data.db` | Webから取得したタイトル、タグ、取得を試みた記録、前回開いたファイル | **別のファイルを開いたとき**、または起動時に内容が変わっていたとき |
| `backups/` | 上記3点セットの世代コピー | 31世代目を作ったとき、古いものから削除 |

起動時は、前回開いていたファイルを自動で開き直します。そのファイルが前回終了時と同じ内容なら「前回の続きを編集しますか？」と確認し、「引き継ぐ」を選べば取得済みのタイトルとタグをそのまま使えます。

## 開発メモ

- Rustワークスペース: `cargo build --workspace` / `cargo test --workspace`
- CI（GitHub Actions / windows-latest）: `cargo clippy -- -D warnings` と `cargo test`
- サーバー単体起動: `cargo run -p nbm-server -- <bookmarks.html>`
- フロントエンドはビルド不要の素のHTML/CSS/JS（`frontend/`）
- 構成: `nbm-core`（ツリー・HTML入出力・DB・バックアップ・AIプロンプト）/ `nbm-server`（axum API）/ `src-tauri`（シェル）

**ビルドが失敗するとき**

- `os error 5 / 拒绝访问` … アプリが起動中。終了してから再実行する。
- `os error 1455 页面文件太小` / `STATUS_STACK_BUFFER_OVERRUN` … メモリ不足。`cargo tauri build --no-bundle -- -j 2` のように並列数を下げる。

## 既知の制限

- コード署名をしていないため、配布したEXEは Windows SmartScreen の警告が出ます。
- 自動更新はありません。EXEの差し替えは手動です。
- UIの自動テストはありません（Rust側のみ）。
- 日本語UIのみです。
- AI分類の品質は、プロンプトとモデルの挙動に依存します。回帰を自動で検知する仕組みはないので、変更後は `logs/ai_classify.log` で確認してください。
